# Security and privacy

This page lists what Rotor protects, what it relies on, and where the limits are.

## Principles

- No server component of its own: notes live in your browser, in files you choose, or in your Drive.
- No telemetry, analytics or remote fonts.
- Nothing is sent to an AI service until you connect an account *and* run an agent (and consent the first time).
- Keys, tokens and passwords are kept out of documents, exports and saved HTML.

## Network surface (CSP)

Each build embeds a Content Security Policy as a `<meta>` tag, generated by `build.mjs`.

| Directive | Standalone | Drive build adds |
|---|---|---|
| `default-src` | `'none'` | |
| `script-src` | `'unsafe-inline' 'unsafe-eval' 'self'` + editor CDNs | `accounts.google.com/gsi/client`, `apis.google.com`, `www.gstatic.com` |
| `style-src` | `'unsafe-inline'` + editor CDNs | `accounts.google.com/gsi/style` |
| `connect-src` | `'self'`, editor CDNs, Cognotik (`cognotik.com`, `*.cognotik.com`, `localhost:*`, `127.0.0.1:*`) | `www.googleapis.com`, `content.googleapis.com`, `accounts.google.com/gsi/` |
| `img-src` | `data: blob: 'self'` | Google avatars/thumbnails |
| `frame-src` | not set (no frames) | Google sign-in and Picker frames |
| `form-action`, `base-uri` | `'none'` | |
| `worker-src`, `manifest-src` | `'self'` | |

The "editor CDNs" are `esm.sh`, `cdn.jsdelivr.net` and `unpkg.com`, used to load Milkdown (the WYSIWYG editor) and its stylesheets.

Honest caveats:

- `'unsafe-inline'` is required because the app code and styles are inlined into the single file.
- `'unsafe-eval'` is permitted for the dynamic-import fallback that loads the editor.
- Milkdown is fetched from public CDNs **without version integrity hashes**. It is pinned to a version in the URL, but you are trusting those CDNs while the editor is loaded. If it can't load, Rotor falls back to a plain textarea, so the notebook never depends on it.

A stricter variant would drop the editor CDNs, `'unsafe-eval'` and the agents' hosts from the CSP. That is a build-time change in `build.mjs`.

## Untrusted content

Note text is untrusted, even your own. Imported files, shared notebooks and anything a model returns are untrusted input.

- **Rendering**: card, list and tooltip rendering uses an escape-first Markdown subset (`model/markdown.js`). All input is HTML-escaped first, and only a fixed set of tags is produced.
  - Links must start with `http:`, `https:` or `mailto:`. They open with `rel="noopener noreferrer"`.
  - Markdown image syntax renders as a link, never as an image, so a note cannot plant a tracking pixel.
- **The WYSIWYG editor** edits Markdown and does not feed untrusted HTML back into the page. Raw HTML in Markdown is escaped on the way out.
- **Embedded data**: when saving HTML, `<`, U+2028 and U+2029 are escaped inside the JSON block, so a note containing `</script>` cannot break out.
- **Import**: files go through `migrate()`, invariants, and JSON parsing only. Nothing in a document is executed.

## Agents

See [agents.md](agents.md). In short:

- off until connected, with explicit first-run consent;
- only the text and labels of the notes in scope are sent, with IDs aliased;
- encrypted notes are never sent;
- proposals only, validated against per-agent allowlists, with deletion not expressible and every referenced note checked against the scope;
- applied only after review, as one undoable step;
- the run log stores metadata only.

Sign-in uses Cognotik's own session cookie in a pop-up. Rotor never sees your password. The optional API key is sent only in an `X-API-Key` header to your configured Cognotik server, which is restricted to `*.cognotik.com` or localhost in both the code and the CSP.

## Keys and tokens

| Secret | Where it lives |
|---|---|
| Cognotik API key | Memory, or `localStorage` (`rotorai:cognotik:key`) if you tick *Remember* |
| Google access token | Memory only |
| Encryption passwords and decrypted text | Memory only |

None of them is serialized into JSON exports, `.rotor` files, saved HTML or Drive files.

## Encryption

See [crypto.md](crypto.md) for the scheme and, importantly, where plaintext can survive (snapshots, undo, earlier file versions, Drive history).

## Reporting issues

Treat the following as security-relevant bugs: any path where note text reaches an HTML sink unescaped, any agent output that can delete or leave its scope, and any secret reaching a saved document.

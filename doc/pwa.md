# Progressive Web App

The static sites produced by the build can be installed as an app and opened from the operating system. Both `dist/` (the standalone page) and `dist/drive/` ship the PWA files.

## Files emitted by the build

For each site folder the build writes:

- `manifest.webmanifest`
- `sw.js`, the service worker
- `icon.svg`, `icon-192.png`, `icon-512.png`

The PNG icons are generated by the build script itself (a gradient ring and dot), so no image tooling is needed. The manifest and service worker are copied from `src/pwa/`, with the entry page name (`rotor.html` or `index.html`) substituted.

A downloaded single file is **not** a PWA. Browsers don't register service workers from `file://`, `blob:` or `data:` URLs. That copy still works offline because everything it needs is in the file.

## Manifest

- `display: standalone`, `theme_color: #6a5cff`, `background_color: #06070e`.
- `start_url` and `id` point at the entry page.
- **`file_handlers`**: the installed app can open `.rotor` files (MIME `application/vnd.rotor+json`) from the file manager.
- **`launch_handler`**: `client_mode: focus-existing`, so opening a second file reuses the open window.

## Service worker

Registered on `https` or `localhost` when the page loads. Behaviour:

- **Install**: precaches the entry page, manifest and icons. Missing optional assets don't fail the install. `skipWaiting` and `clients.claim` are used.
- **Activate**: deletes caches whose name differs from the current one (`rotor-pwa-v1`).
- **Never intercepted**: requests to `*.cognotik.com`, `googleapis.com`, `google.com`, `gstatic.com` and any `/api-proxy/` path. Agent and Drive calls always go straight to the network.
- **Other GET requests**: serve from cache if present while refreshing the cache in the background; otherwise use the network and cache successful same-origin responses.
- **Navigations with a query string** (Drive's `?state=…` launch URLs) always go to the network first. If offline, the cached app shell is served regardless of the query.

When shipping a new version, bump `CACHE_NAME` in `src/pwa/sw.js` so existing installs drop the old cache. There is no in-app "update available" prompt.

## Launch queue and drag-and-drop

`pwa.js` registers a `launchQueue` consumer, so files opened with the installed app load straight into the notebook and the file handle is kept for in-place saving.
Dropping a `.rotor`, `.json` or `.html` file anywhere on the window opens it.

## Installed-app behaviour

- Rotor detects installation via `display-mode: standalone` / `window-controls-overlay`, `navigator.standalone`, the `appinstalled` event and the launch queue.
- When installed (and not in the Drive build), the Save button reads **Save .rotor file** and `Ctrl/Cmd+S` saves as `.rotor`. In a plain browser tab it reads **Save as HTML file**. In the Drive build it reads **Save to Drive**.

## Storage caution

Browsers may evict storage for sites that are not installed, and sometimes even for installed ones. Keep saving to files (or Drive). See [storage.md](storage.md).
